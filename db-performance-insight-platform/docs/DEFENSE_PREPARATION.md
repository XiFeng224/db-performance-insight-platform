# 答辩准备（当前版本）

> 目标：用 8~10 分钟讲清“为什么做、做了什么、比现有方案强在哪、是否可落地”。

---

## 1. 推荐答辩结构（10 分钟）

## 1.1 选题背景（1 分钟）

- 中小团队和高校实验室缺少低成本、可解释的数据库诊断平台。
- 商业工具（如 DBdoctor）功能强，但成本和可定制度门槛较高。

一句话：
> 我们做的是一个兼顾工程可落地与教学可复盘的数据库性能智能诊断平台。

## 1.2 架构与技术路线（1 分钟）

- 前端：React + TypeScript + AntD + 图表
- 后端：FastAPI + SQLAlchemy + MySQL
- AI 侧：趋势、异常检测、建议生成
- 运维侧：实例、变更风险、容量、Runbook、留痕

## 1.3 核心演示（4~5 分钟）

建议路径：
1. 平台首页（模块化入口）
2. 运维中心：
   - 实例管理（分组/筛选）
   - 会话锁诊断
   - 变更风险评估
   - 容量 7 天预测
   - Runbook 自动生成
3. AI 诊断页：
   - 证据链
   - 根因概率
   - 冲突检测
   - SLA 评估
4. 操作留痕：
   - 后端持久化
   - 筛选、导出、自动刷新、详情

## 1.4 对标与创新（1.5 分钟）

### 借鉴 DBdoctor 的地方
- 诊断闭环思想
- 运维模块化视角
- 工程可追踪（留痕）

### 我们的创新
- 可解释证据链（trace_id + evidence chain）
- 根因概率图（Top-K）
- 建议冲突检测
- SLA 视角评估
- 教学友好的复盘路径

## 1.5 落地与价值（1 分钟）

- 已具备完整产品形态（不是实验脚本）
- 可用于：课程实验、竞赛展示、中小团队日常 DBA 支持

## 1.6 未来计划（30 秒）

- 鉴权与 RBAC
- 多数据库支持（PostgreSQL / MongoDB）
- 规则自学习与评估闭环

## 2. 演示口径（可直接说）

> 我们不是单点做“慢查询工具”，而是构建了从发现问题、解释问题、给出建议到执行与留痕的完整链路。  
> 在借鉴 DBdoctor 的工程思路基础上，重点强化了可解释 AI 与教学复盘能力。

---

## 3. 评委常问问题与建议回答

### Q1: 你们和 DBdoctor 的差异是什么？
A:
- 借鉴其闭环能力，但我们强调可解释（证据链/根因概率）和教学复盘。
- 我们做了更轻量、低门槛、可定制的开源路线。

### Q2: AI 建议是否可信？
A:
- 我们不只输出建议，还输出证据节点、置信度和影响预测。
- 同时提供冲突检测和 SLA 风险视角，辅助决策而非盲目自动执行。

### Q3: 能否在生产用？
A:
- 当前已具备工程骨架：模块化接口、日志留痕、降级策略。
- 生产落地需要补齐：鉴权、灰度策略、审计权限、HA 部署。

### Q4: 数据不全时是否可演示？
A:
- 支持降级/示例数据，确保演示稳定。
- 同时保留真实 MySQL 接入路径。

## 4. 演示前检查清单

- 后端 `8000` 是否启动
- 前端 `3000` 是否启动
- `/docs` 是否可打开
- 运维中心能否正常加载

- 操作留痕是否能写入与查询

## 5. 评分点对齐提示

- **选题价值**：低成本替代 + 教学落地
- **技术难度**：AI + 规则引擎 + 可视化 + 运维编排
- **完整度**：主页、模块、接口、留痕、导出
- **创新点**：可解释 AI + 概率根因 + 冲突检测 + SLA
- **行业视野**：对标商业工具并做差异化取舍

> 它借鉴商业工具的闭环能力，同时在 AI 可解释性与复盘链路上做了创新，具备持续演进到生产级的基础。
