# 答辩准备（当前版本）

> 目标：8~10 分钟讲清“为什么做、怎么做、亮点在哪、是否可落地”。

---

## 1. 推荐答辩结构（10分钟）

### 1.1 选题背景（1分钟）
- 高校实验室值班工作存在多系统割裂、应急协作不标准、复盘困难等痛点。
- 传统方案常停留在“监测/报修”单点能力，缺少闭环联动。

一句话：
> 我们做的是一个把告警、工单、应急和复盘打通的校园实验室智能应急协作平台。

### 1.2 架构与技术路线（1分钟）
- 前端：React + TypeScript + Ant Design
- 后端：FastAPI + SQLAlchemy + SQLite/MySQL
- 运行：Nginx + systemd
- 智能能力：规则引擎 + AI辅助（带回退机制）

### 1.3 核心演示（4~5分钟）
建议路径：
1. 登录页进入（演示账号）
2. 告警响应中心：告警分级 + 一键转工单
3. 工单中心：派单/ETA/状态流转 + 责任链时间线
4. 应急协作中心：Runbook执行 + 操作留痕 + 风险扩散预测
5. 复盘中心：首响时长、闭环时长、SLA超时率、AI回退率

### 1.4 对标与创新（1.5分钟）
参考论文方向：高校实验室物联网监测与云平台应急管理。

本项目创新点：
- 告警一键转工单（上下文自动注入）
- SLA超时自动升级（流程自动化）
- 工单风险评分自动分级
- 应急剧本模板化与操作留痕
- 演示模式/降级机制保障稳定展示

### 1.5 落地价值（1分钟）
- 可直接服务校园实验室值班协作。
- 数据可追溯、责任可量化、复盘可闭环。
- 具备向院系/校级协同扩展能力。

### 1.6 未来规划（30秒）
- RBAC权限与多角色视图
- 与门禁/视频/IoT平台联动
- 演练报告自动生成与导出

## 3. 评委常问问题与建议回答

### Q1: 你们和普通报修系统有什么区别？
A:
- 我们不仅报修，还做告警联动、应急剧本、SLA自动升级和复盘评估。
- 是“应急协作平台”而非单点报修工具。

### Q2: AI如果失效怎么办？
A:
- 采用规则+AI双轨。
- AI失败自动回退规则引擎，保障核心流程不受影响。

### Q3: 如何证明系统可落地？
A:
- 已采用 Nginx + systemd 部署。
- 提供健康检查、演示数据脚本、文档化部署与演示清单。

### Q4: 数据不全时能否演示？
A:
- 可执行 `seed_demo_data.py` 一键注入全模块样例数据。
- 支持演示模式开关，确保赛场稳定展示。
